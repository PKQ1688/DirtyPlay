# DirtyPlay 回归验证

根据本次需求、diff 和失败日志确定受影响行为；用户指定的范围优先。读取仓库 [开发工作流](../../../docs/workflow.md) 中对应的环境、检查与场景说明。

- Go 从受影响包开始，跨模块或并发改动再扩大检查。
- Web 使用现有 npm 入口和精确的场景筛选。先确认测试服务对应当前代码；自行启动时使用空闲本地端口，结束后清理自己的进程。
- 协议改动检查 Web/Godot 消费方与玩家视图隔离；Godot 无法运行时，报告具体未验证路径。
- 读取本次生成的汇总和相关截图，确认目标场景确实执行；语法检查不等于行为回归，随机技能未覆盖不等于通过。
- 失败时结合日志定位原因，再决定修复或重试；通过且无新证据时结束验证，不靠反复运行获得绿色结果。

交付简短说明：检查范围、实际结果、证据路径及未覆盖项。环境缺失时完成其余可执行检查，并说明缺少什么。
